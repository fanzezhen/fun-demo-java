## 核心原则

### 1. 不要重复实现框架功能

在编写新代码前，必须先查阅父项目 fun-framework-java 的 后端脚手架.md

- 父项目文档位置: `C:\code\fanzezhen\fun-framework-java\doc\dev\提示词\专业提示词\后端脚手架.md`
- 优雅降级策略: 本地文件 → GitHub Raw → Gitee Raw
- 本项目职责: 演示如何使用框架能力，而不是重新实现

### 2. 演示代码的质量标准

- 完整可运行 - 提供完整的代码示例，包括配置文件
- 最佳实践 - 使用框架推荐的方式，避免反模式
- 清晰注释 - 关键位置添加中文注释说明用法和注意事项
- 测试覆盖 - 提供单元测试和集成测试演示
- 边界情况 - 展示常见场景和边界情况的处理
- H2 数据库优先 - 确保用户零配置即可运行

### 3. 依赖管理原则

- 父项目继承: 本项目继承 fun-framework-java
- 版本统一: 所有依赖版本由父项目 pom.xml 统一管理
- 模块化设计: 每个演示模块独立，依赖明确

## 常见场景快速指南

### 场景 1: 需要写一个新的 REST API

1. 读取父项目 `后端脚手架.md` → 确认统一返回格式、异常处理、参数校验
