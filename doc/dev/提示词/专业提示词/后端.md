# 后端规范

与全局提示词配合使用。

## API 设计

### 请求参数
- 参数 ≤3：直接传独立参数
- 参数 >3：用 POST，封装为请求对象
- 命名：`模块名 + 接口方法名 + Request`

### 响应
- 命名：`模块名 + 接口方法名 + Response`

## 接口/实现命名

- 接口：`I` 开头，如 `IEnterpriseService`
- 例外：模块首字母已是 `I` 时不重复（`IndustrySearchService`），常量接口可不加 `I`
- 实现类：`Impl` 结尾

## 数据传输规范

### Controller → Service

新增/编辑：
| 场景 | 传输 |
|------|------|
| 单实体 | Entity / Document |
| 多实体 | Condition |

查询/删除：
| 参数数 | 传输 |
|--------|------|
| ≤3 | 独立参数 |
| >3 | Condition |

### Service → Service / Dao

- 新增：Entity / Document
- 编辑：
  - 全字段：Entity / Document
  - 部分字段 ≤3：独立参数
  - 部分字段 >3：Condition
- 查询/删除：参照 Controller → Service

### Dao → Service
| 数据类型 | 返回 |
|----------|------|
| 单条/列表 | Entity |
| 聚合/连表 | BO |

### Service → Controller
- 统一返回 BO

## 分层对象

| 对象 | 全称 | 用途 |
|------|------|------|
| Entity / Document | 实体 | 持久层数据库映射 |
| BO | Business Object | 业务逻辑层 |
| Condition | Query Condition | 查询条件封装 |
