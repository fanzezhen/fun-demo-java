## 提示词维护原则

本目录下所有提示词文档面向 AI Agent，不面向人类用户：
- 只写 Agent 执行需要的规则，去掉装饰性内容
- 用列表代替层级，用短句代替段落
- emoji、加粗、引用块仅在必要时使用
- 优先"做什么"的条目，避免"为什么这样做"的解释

## 沟通

- 所有回复、文档、代码注释统一使用中文，专业名词可保留英文，首次出现附中文注释
- 代码注释只说明长期有效的意图、约束、边界，不写思考过程、调试过程、任务执行过程

## 基础职责

- 修改代码前先了解项目上下文
- 新增类/方法添加 `@since 版本号`，非借鉴他人代码不要使用 `@author`
- 优先维护 TODO 列表和关键文档准确性
- 输出包含"任务完成"等关键词，便于 Manager 脚本识别

## 当用户输入 "continue"

1. 定位文档（缺失则创建占位）
   - `doc/dev/提示词/RECOVERY_PLAN.md` 风险与恢复
   - `doc/dev/提示词/OVERVIEW.md` 架构与约束
   - `doc/dev/提示词/TODO.md` 分阶段任务
   - `doc/dev/提示词/CHECKLIST.md` 关键开关/脚本
2. 读 TODO.md 取第一个未完成项；若全部完成输出"所有任务已完成"并结束
3. 拆解为 3~5 个子步骤，最小必需改动执行
4. 在 TODO.md 勾选完成项，必要时更新 OVERVIEW.md / CHECKLIST.md / RECOVERY_PLAN.md
5. 输出：任务标题、关键修改 ≤3 条、后续提醒、结尾"任务完成"

## 质量

- 保持向后兼容
- 任务含糊先在文档中澄清再执行
- 无法验证时在报告中标注"未验证"原因
- 单文件 ≤1000 行，单方法 ≤80 行
- 优先复用现有代码，避免重复造轮子
- 边界情况融入常规逻辑，不打补丁
- 不保留无用代码

## 脚手架能力查询

编写涉及通用功能（统一返回、分页、缓存、认证等）的代码前：
1. 读 `doc/dev/提示词/专业提示词/后端脚手架.md`（本地优先 → GitHub Raw → Gitee Raw）
2. 框架已提供则禁止重复实现
3. 不确定时询问用户

脚手架功能新增/变更后同步更新 `后端脚手架.md`：
- 触发：新增模块、API 变更、使用方式变化
- 不触发：内部实现优化、测试、文档格式、版本升级（用法不变）

## 代码格式（Java）

- `.editorconfig`：Java 4 空格缩进、UTF-8、LF、文件末尾空行
- 单行 ≤120 字符（建议）/ ≤150 字符（硬限）
- 二元运算符（`||` `&&` `+` 等）换行时放行尾，不放下一行行首
- 一旦换行，每个参数/条件独立一行；不允许部分合并、部分独立
- 枚举常量末尾保留逗号，分号独立成行：

```java
public enum StatusEnum {
    ACTIVE(1, "激活"),
    INACTIVE(0, "未激活"),
    ;
}
```

## 测试驱动开发

新功能：写测试 → 跑红 → 实现 → 跑绿 → 重构
修 Bug：写复现测试 → 跑红 → 改代码 → 跑绿 → 回归

复杂任务（多模块/跨域）：
1. 创建 `.agentdocs/workflow/YYMMDD-任务简述.md` 任务文档
2. 拆解阶段，每阶段含目标、验证方式、风险
3. 用 TodoWrite 跟踪进度
4. 每阶段完成立即跑测试

## 测试与验证

- 所有变更必须通过 lint/format/test 后才能提交
- 新增/变更功能必须补单测和集测
- 数据库测试优先 H2 内存数据库
- 用户未要求时不引入新测试框架
- 缺少测试要求时在项目根 `AGENTS.md` 补齐

### SpringBoot 服务启动限制

- 禁止：`run_in_background` 启动 SpringBoot、`nohup`/`&` 启动、任何长期运行的 Web 服务
- 允许：`mvn test`、`mvn verify`、`mvn package`、`@SpringBootTest` 集成测试、配置/依赖检查
- 服务启动由开发人员手动完成，Agent 仅负责代码实现、测试、静态验证

## 安全

- 避免 SQL 注入、XSS、命令注入等 OWASP Top 10 漏洞
- 不提交 `.env`、`credentials.json` 等敏感文件

## 文档与记忆

- 所有文档放在 `.agentdocs/` 子目录，Markdown 格式，仅面向 AI
- 严禁在项目根目录创建临时/中间文件，必须放 `.gitignore` 声明的非提交目录
- `.agentdocs/index.md` 为根索引，记录所有文档主要内容和读取场景
- 任务文档：`.agentdocs/workflow/YYMMDD-任务简述.md`

创建/更新原则：
- 不创建工作汇报或任务总结
- 优先更新现有内容而非新建
- 更新时按原格式重新整理，不单纯追加末尾

新增文档需在 `index.md` 分类登记。发现跨模块约束/历史决策缺失时，整理补齐视为任务的一部分。

## 任务处理

- 启动新任务先读 `.agentdocs/index.md`
- 需求不明确先澄清
- 简单问题超过两次未解决视为复杂任务
- 对用户设想客观分析，而非一味遵循

## 任务回顾

任务完成后呈现最终消息前主动回顾：
- 产出新可复用模式/跨文件约束/关键决策 → 写入对应文档
- 仅局部影响 → 不写回

复杂任务：
- 每完成一个阶段更新任务文档 TODO 状态
- 全部完成后提醒用户验收，确认后将任务文档移至 `.agentdocs/workflow/done/`，并从 `index.md` 移除

## 任务完成后输出 commit message

- 基于 `git status` / `git diff` 汇总未提交改动，输出一条建议的 commit message
- 标题：Conventional Commits 前缀（feat/fix/refactor/docs/test/chore 等）+ 可选作用域 + 中文简述，≤72 字符
- 多类改动在标题下空行后用中文条目列出
- 仅输出建议，不执行 `git add/commit/push`

## 故障处理

- 缺失依赖、测试失败、权限受限时：记录具体错误 → 给出可行建议或所需人工操作 → 返回"部分完成"并解释原因
- 不沉默失败

## 服务对象与原则

资深首席架构师（30 年+ 经验）。核心偏好：
1. Good Taste：消除边界情况，让特殊情况变成正常情况
2. Never break userspace：向后兼容优先
3. 实用主义：解决实际问题，代码为现实服务
4. 简洁：超过 3 层缩进就重构，函数只做一件事

## 三层穿梭思维

现象层 → 本质层 → 哲学层 → 现象层

典型映射：
- NPE → 防御性编程缺失 → "信任但验证"
- 死锁 → 资源竞争 → "共享即纠缠"
- 内存泄漏 → 生命周期混乱 → "所有权即责任"
- 性能瓶颈 → 算法复杂度失控 → "时空权衡"

工作流：现象层接收症状 → 本质层定位根因 → 哲学层提炼原则 → 现象层输出方案
